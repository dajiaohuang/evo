# Evo 数据与创作平台 v2

2026-10-20。用户已授权重新设计数据结构、转写并上传；创作模式确定为“用户与 AI 创作，网页审核与发布”。本文件规定目标结构和切换条件，不代表迁移、生产接入或网页已完成。当前规范 Markdown/YAML 在完成切换前仍然是权威。

2026-10-21 补充目标：用户在多台电脑上并行运行 worker，分别编辑不同主题或类群的页面，向同一个服务提交数据库草稿，再由网页审核发布。任务领取、基线版本、节点冲突检测、独立 worker 身份和幂等提交的具体缺口与协议见[完整迁移与多电脑 worker 盘点](cloud-migration-inventory-2026-10-21.md)。这些服务尚未实现；现有通用 outbox 表不等于已有可用的并发 worker 平台。

页面与完整依赖的结构已进一步实现为[页面依赖模型](page-dependency-model.md)：增加类型化版本图、双向使用查询、发布封存，以及页面和共享节点两层草稿版本比较。该链接记录当前原生数据库实现；此前盘点中的“草稿 CAS 尚未实现”仅描述当时状态。HTTP API、worker 身份/任务服务和网页审核仍未接通。

## 1. 选型与部署

采用 **Vercel + Neon PostgreSQL + 私有 Vercel Blob**。PostgreSQL 管身份关联、内容版本、书目、引用依赖、创作事务和发布；Blob 管不可变的完整正文/证据载荷、原始材料、图像和压缩数据包。一个正文与证据聚合只保存一份，数据库中的散列、身份索引和版本引用均从该聚合派生。

| 方案 | Evo 中的适用性 | 决定 |
| --- | --- | --- |
| Neon PostgreSQL | 关系约束、事务、版本化内容；Vercel 原生集成和预览分支 | 首选；使用已有新建资源，不再创建第二个同用途项目 |
| Supabase PostgreSQL | 需要完整账号、实时订阅、文件与管理后台一体时有价值 | 可替代；当前创作模式不要求实时多人合写 |
| MongoDB / 图数据库 | 可存文档或图，但不能直接消除科学身份、版本、事务和出处约束 | 不作为首期主库 |
| Redis | 限流或热点缓存 | 有测量证据再增加；不是科学内容权威 |
| 浏览器 IndexedDB / DuckDB | 私人工作区、离线核心、临时分析 | 继续保留其现有职责，不承担共享正式内容 |

当前 Web 是 React/Vite 静态客户端；Vercel 通过静态产物部署。Go 服务读取冻结文件，启动装入分类树。目标 Web 继续部署 Vercel，新的短请求 API 与数据库同区域部署；批量转写、OCR、压缩和发布构建由可恢复的后台任务执行。现有 Go 导入与验证能力可继续做工作进程，不把整份数据目录装进每个请求函数。

已创建 Vercel 管理的 Neon 资源 `evo-authoring-v2`，项目 `dry-pine-48288359`，资源 `store_yjugdTfzhH6MdKhi`，区域 `sin1`，套餐 `free_v3`；仅连接开发与预览。Auth 开启，Realtime 关闭。生产接入在验收后执行。数据库连接信息只放本机忽略的环境文件和 Vercel 环境变量，浏览器不能取得连接口令。

官方依据：[Vercel 存储](https://vercel.com/docs/storage)、[Neon 与 Vercel 集成](https://neon.com/docs/guides/vercel-overview)、[Supabase 集成](https://supabase.com/docs/guides/integrations/vercel-marketplace)、[Vercel 函数限制](https://vercel.com/docs/functions/limitations)。

## 2. 已核实的迁移规模

本机内容构建摘要：139,458 个规范节点目录、476,984 个源文件、140 个投影。整合提交前 Git 内容树为 1,633,211,700 字节，其中证据 YAML 944,555,882 字节，英文正文 303,044,810 字节、中文正文 264,082,806 字节；最终转写以推送后的确切 Git SHA 重新计数。

COL26.8 冻结清单包含 2,429,092 个树节点、2,429,088 条直接父子边及 4 个根；名录清单的全源名称用法统计为 5,425,409，已纳入名称用法统计为 4,248,569。这些口径不同，不能把树节点数当作全文内容数，也不能把本地已导出分区冒充完整上游归档。

先用真实内容和分类样本测 `pg_database_size`、表与索引大小，再决定导入批次。1.63 GB 源文本不能直接等同数据库大小：正文规范化、重复出处去除和数据库压缩会改变占用，而索引、版本历史和预览分支会增加占用。免费额度不构成全量容量承诺。上传器必须有空间水位、批次收据与恢复点；不能在额度错误后重复整批写入。

费用只按实测估算：数据库计算量、数据与历史容量、对象容量、读取传输、操作次数和预览分支分别计算。当前参考：[Neon 价格](https://neon.com/pricing)、[Blob 价格](https://vercel.com/docs/vercel-blob/usage-and-pricing)。不把官网示例月费当成本应用账单，不自动升级收费套餐。

## 3. 数据权威与版本

1. **外部科学身份**始终由实际来源和版本限定，例如 `(COL, COL26.8, 6G5JP)`；PBDB、标本、地点、研究材料各自独立。数据库 UUID 只是内部键，不是新的科学编号。
2. **来源版本**不可变：归档 SHA、版本、取得时间、原始定位和权利信息完整保留。COL 发布版本、来源 checklist ID 与应用发布版本是三个字段。
3. **内容修订**不可变。正文与证据的一次修改生成一个新修订；旧发布仍能解析原修订与原书目。名称匹配不能自动产生概念等价关系。
4. **正式发布**钉住节点修订、书目修订、分类来源版本、代码/codec 版本和文件散列。用户一次会话内不混用发布版本。
5. **一次性切换权威**：迁移前文件可写、数据库为核对副本；切换后数据库为创作权威、Git 文件为可复现导出。禁止长期双写，也不允许网页改数据库、AI 同时改旧 YAML 而没有冲突检测。

## 4. 结构与约束

### 分类和对象

| 表 | 核心字段与约束 |
| --- | --- |
| `source_release` | authority、release_key、source URL、archive SHA、raw metadata；来源版本唯一 |
| `source_checklist` | `(release_id, source_dataset_id)` 唯一；保留原始名称和出处 |
| `taxon_usage` | `(release_id, usage_id)` 主键；name、authorship、rank、status、parent、accepted target、source checklist；所有关联必须处于同一来源版本 |
| `content_node` | internal ID、node kind；不从目录名推断科学身份 |
| `node_revision` | node、parent revision、identity、typed relationships、content hash、creator；身份仅保存来源实际给出的字段 |

直接子级采用紧凑 `(release_id, parent_id)` 索引，命中一个父级的实际子集后按已声明顺序分页。祖先查询使用有深度与循环保护的递归或独立派生路径缓存，不预先生成全部祖先闭包。全部 730 个冻结名称搜索分片保留在对象存储中，沿用明确的规范化和路由语义；当前没有再给 SQL 分类树复制一份全量名字模糊索引。有真实查询负载后再决定是否增加 [pg_trgm](https://neon.com/docs/extensions/pg_trgm)；中文全文检索必须以真实中文语料测试。地理查询按需启用 [PostGIS](https://neon.com/docs/extensions/postgis)。

`source_dataset_id` 为原始来源版本内的 checklist ID，允许上游真实缺失的空值，不能补造。本次发现的 6G5JP 错配应在导入前通过精确来源记录比对被拒绝；仅有“这个 checklist 存在”的外键还不够。

### 正文和证据

首期落地将 `node_section`、`evidence_record`、`evidence_binding` 作为聚合内的逻辑结构：不可变载荷保留 `node`、原始 `evidence` 和按语言保存的 Markdown `pages`。基线修订的 `payload_artifact_sha256` 指向已逐字节核验的私有压缩对象，使用真实修订 UUID 选择唯一记录；`identity`、源文件散列和投影入口保留在数据库用于索引。小型新草稿也允许内联 `document`。读取时重算完整内容散列并比较身份、源文件和入口，不能把载荷丢失解释成空正文。

`revision_dependency` 只保存“修订 → 书目版本”的边；书目的内部 `version_id` 不是新科学 ID。每段的实际来源、原定位、摘录和使用范围保留在同一载荷中，不在依赖索引里复制一次。章节读取和网页编辑继续遵守现有键控 Markdown 语义。下面是逻辑模型，不表示所有名称都是独立物理表。SQL、程序与实际迁移状态见 `database/` 和执行收据。

修订身份同时考虑内容与引用的书目版本；只改书目元数据也能形成新修订。相同正文可通过 `payload_record_id` 复用同一不可变对象记录，而不会把新修订错误折叠到旧版本。当前基线使用其已核实的冻结修订 ID；后续导出在清单中明确修订身份算法版本。

| 表 | 核心字段与约束 |
| --- | --- |
| `node_section` | `(revision_id, locale, section_key)` 唯一；顺序、真实标题、Markdown 正文；正文只保存一次 |
| `evidence_record` | revision、record_key、schema version、结构化证据 JSONB；保留完整取样范围、测量、限定和来源绑定，不强拆成虚假的事实碎片 |
| `reference_revision` | 稳定 reference ID、修订 hash、完整原始字段 JSONB；作者、日期精度、元数据变体和权利信息不丢失 |
| `source_snapshot` | 原文件 hash、字节数、媒体类型、对象位置、取得时间、权利依据；未知转载权的扫描保持私有 |
| `evidence_binding` | 修订、record/section 稳定键、reference revision、可选 snapshot、原定位、摘录、用途与范围 |

正文结构、卡片导语和地图气泡遵循现有节点制作标准。短版为有出处的编辑表达，不机械截断，也不生成正文没有的事实。英中正文分别保存；翻译缺失不伪装成已完成。审核记录属于创作工作区，公众科学页面不显示“专家评审分数”或内部维护状态。

年代以原始精度保存，未知值为空并附原记录的未知原因。现代与古坐标分别存储，古坐标附模型与版本；标本取样、记录地点与类群分布分别建模。分类树、策展导航、系统发育假说是不同的关系类型。

### 创作和发布

| 表 | 核心字段与约束 |
| --- | --- |
| `change_set` | base release、作者/AI run、预期旧修订、修改清单与幂等键；是一次提交对象，不给每个节点增加制作台账 |
| `validation_run` | 确切 changeset hash、validator version、检查结果与产物 hash；旧版本通过结果不能批准新内容 |
| `publication_approval` | 用户身份、确切候选 hash、批准时间；AI 不能给自己授予发布权限 |
| `outbox_job` | 与变更事务一同写入；任务 ID、输入 hash、步骤、租约、结果收据；重试先查已知收据 |
| `release` / `release_item` / `release_reference` | 不可变发布及其内容、书目和分类依赖清单 |
| `artifact` / `channel` | 内容寻址产物、字节数、SHA、可见性；唯一生产 channel 原子指向已完成发布 |

用户私人笔记与查询历史是独立用户数据；保留现有本机 IndexedDB，日后同步时以 owner 和版本隔离，不混入科学节点或全局书目。

## 5. 你和 AI 的创作链路

1. **领取对象**：按确切来源版本和 ID 打开创作任务，读取当前正式修订与已有材料。AI 只取得该 changeset 所需写权限。
2. **整理来源**：保存原材料、SHA、版本、定位、摘录和权利证据；缺失身份、日期或概念映射时保留未知。
3. **编写同一份内容**：AI 或用户提交正文、证据绑定、真实关系及英中内容；从正文编辑摘要。客户端暂存可以丢弃，不覆盖正式修订。
4. **预检和预览**：先做 schema、来源版本、身份、书目日期、引用、关系与语义范围检查；再生成这次受影响的节点与视图。网页并排展示正文、来源定位、差异、卡片/阅读窗/地图与树的实际预览。
5. **用户审核发布**：批准确切候选 hash；发生冲突返回差异，编辑后重新验证。准备所有产物并校验 hash、引用闭包和可达性，再原子切换生产发布指针。失败保留上一个发布；回滚仅切回旧发布，不覆盖来源或修订历史。

网页主动作依次为“整理材料”“生成草稿”“预览差异”“发布本次修改”；身份、来源与正文就近可见。批量任务按 changeset 展示总体结果，失败项可单独恢复，不要求用户理解 SQL、队列或存储桶才能创作。

## 6. 增量发布和 API

依赖图按 `内容修订 → 实际使用的书目修订/材料/相关对象 → 对应视图与包` 记录。修改一个来源只重算直接依赖对象和相关包；书目不再完整水合复制进每份正文。发布清单复用旧产物 hash，以 Merkle/内容寻址的清单汇总完整性。完整全库校验保留在迁移与周期审计中，普通发布不重新读取 47 万个未变源文件。

发布构建与请求读取分离。短请求只读取指定发布的、有索引的少量行。大文件从授权对象位置交付，不通过数据库行或每次函数响应中转；上线前实测下载 hash、Range/If-Range、缓存与 CORS，不能假设新对象服务天然满足旧协议。

现有协议严格声明 `packed-adjacency`；SQL 实现不能继续虚报内部表示。新增 `/v2/capabilities`，声明真实 `indexed-relations`，保留明确 release ID、直接子级分页、按需读取和各平台范围。新增节点正文/证据与祖先路径端点，发布指针作为请求入口；cursor 绑定发布、父节点、排序与查询，不能跨版本复用。v1 服务在旧客户端过渡期仍固定自己的不可变发布；v2 Web/Android/iOS 各自通过实际契约验收后切换。原生 App 仍只携带 `native-core`，不会启动时同步全库。

## 7. 转写与上传顺序

1. 完成当前有效更新的 main 推送，固定 `git SHA + source manifest hash`。旧工作树清理与新平台目录分开处理。
2. 对该 Git 快照作确定性流式转写：原始文件 hash、节点身份、键控正文、证据和全局书目均保留；UUID 采用稳定输入派生的内部映射。文件路径仅作为迁移定位记录，不复制进新科学身份。
3. 在新数据库的独立 schema/分支运行受版本管理的迁移；真实小批样本往返重建并比较字段、正文、来源、未知值和 hash。记录真实表/索引占用后启动全量批次。
4. 按批次 hash 幂等上传，逐批核对数量与摘要；对象文件先上传、校验后登记数据库。中断通过任务/批次收据续传，未知写入不能直接重放。达到容量水位先停止，不自动升级。
5. 完整核对原节点数、源文件数、书目数、分类树与名称口径、引用闭包、精确版本字段、英中页面内容和生成视图。孤儿、重复或错误出处必须为 0；来源本来缺失的字段仍缺失。
6. 验收“登录 → AI 提交草稿 → 网页来源与差异预览 → 用户发布 → 公共读取新版本 → 原生范围与离线包验证 → 回滚”完整链路。然后才将新服务连接生产环境并切换权威，保留可恢复的旧正式快照。

数据库结构创建成功、数据上传成功、完整转写核对、网页功能完成和生产切换是不同结果。执行收据应逐项记录实际状态，不把准备完成写成上线完成。

## 8. 本轮实际完成的边界

已完成数据库与私有 Blob 的创建和开发/预览接入、版本化 SQL 迁移、139,458 个节点与 5,255 条书目的转写、374,950 条引用依赖核对、2,429,092 个分类树节点的原生 SQL 导入，以及全部 1,572 个对象的下载散列核验。原始源归档保留 476,984 个文件，冻结名字搜索分片和必要研究来源保持独立。

完整内容读回验证包括“PostgreSQL 修订记录 → 私有 Blob → 解压 → 选择唯一修订 → 全字段与内容散列比较”，覆盖五个采用节点与一个真实未记录 kind 的阅读指南。完整分类事务核对树节点、父子边、根、物种数及九组真实节点/子级查询；数据库约 837 MB，未升级收费套餐。

旧的全载荷入库在容量水位处安全停止；改为不可变对象载荷并精简派生引用索引后，完整内容与分类树均通过。重建仅涉及新库未发布的导入暂存副本，先逐字段核对其可恢复对象；原文件、Auth、来源材料和已发布数据均未被清空。

本轮没有实现网页审核台、启用公开 v2 API、切换生产读取或替换现有前端。目标创作链路已定义，正式切换仍需第 7 节的实际链路验收。详细版本、数量、原生验证与资源信息见 [执行收据](evo-data-platform-v2.execution.json)。
