# 完整云端迁移与多电脑 worker 盘点

盘点日期：2026-10-21（Asia/Singapore）。本轮只读检查本地文件、现有数据库、Blob 对象目录和线上发布清单，没有上传、删除、部署或切换内容权威。容量使用十进制 MB/GB。

## 目标与当前状态

目标是用户在不同电脑上并行运行 worker，分别编辑不同主题或类群的页面，提交到共同的数据库草稿区；网页统一查看来源、修改差异和预览，由用户审核发布。worker 运行在用户的电脑上，Vercel 承担协调 API、审核网页与公共交付。各电脑不需要复制整套来源仓库。

当前正式科学内容仍以规范文件为权威。新库是已核对的迁移快照；本文件描述的任务服务、worker 提交协议和审核界面尚未实现。正式切换后数据库成为创作权威，Git 内容文件成为可复现导出，避免数据库与旧文件独立双写。

## 去重差额与容量预算

对 `data/` 全部 52,533 个文件读取实际字节并计算 SHA-256，得到 52,378 个不同内容的文件，共 3,919,441,158 bytes；其中 988 个内容与既有 Blob 上传收据完全一致，216,929,037 bytes。尚未进入新 Blob 的不同内容有 **51,390 个，共 3,702,512,121 bytes（约 3.70 GB）**。同一 hash 的本地重复副本共约 4.11 MB，已排除在差额中。此次比较保留现有压缩文件的原始压缩字节，没有假设额外压缩率。

| 方案 | Blob 容量 | 计算与边界 |
|---|---:|---|
| 当前已有 | 0.745 GB | 实际对象目录 |
| 保留已有对象并补全整个 data 仓库 | **4.447 GB** | 744,828,756 + 3,702,512,121 bytes；按 hash 去重的精确差额，尚未上传 |
| 上述再保守加入整个 docs 目录 | **不超过约 4.641 GB** | 未对 docs 做内容 hash 去重，属于保守上界；包含作者辅助资料 |
| 再额外保留一份现有 full-web 交付载荷 | **不超过约 5.552 GB** | 再加约 0.910 GB，不抵扣与 data/既有 Blob 的重叠；发布清单少量开销另计 |

因此完整云端数据与来源档案的**初期 Blob 工程预算按 6 GB 基线、10 GB 预留**较合理；如果交付载荷继续由 Vercel 静态部署承担，则不必再复制一份到 Blob。后续新增原始材料、图片、多次历史发布及中间产物会增加容量；此处没有包含未知未来数据，也没有升级套餐。

Neon 目前 837 MB，分类表及其索引约 522.52 MB，节点修订约 184.54 MB，引用依赖约 57.92 MB。多电脑并行本身不要求每电脑复制一份全库；新增任务、候选、修订和发布历史才会增长。维持大正文与来源在对象存储的结构，**Neon 初期按 2–3 GB 预算**，在真实 worker 版本保留策略落地后再校准。这个预算不是实测未来占用，也不是任何套餐额度或账单报价；不包含另建全量名称 SQL 搜索索引、额外数据库分支和供应商历史保留的未测成本。

## 多电脑 worker 提交协议

1. **按来源身份拆任务。** 用户指定类群或主题范围；服务端将任务固化为来源版本和明确 node ID 集合。跨类群主题也用明确节点集合，不能仅凭名称或路径划分；PBDB 与 COL ID 不互相猜测等同。worker 只领取有权限的任务。
2. **领取并取得基线。** 服务端原子领取任务，给出 `task_id`、`lease_epoch`、到期时间、每节点 `expected_revision_id`、书目版本及最小内容/来源包。worker 定期续租；续租过期后旧 epoch 的提交必须拒绝。租约减少重复劳动，版本比较仍是最终防覆盖检查。
3. **在本机与 AI 编辑。** worker 使用相同的规范结构和校验器编辑 Markdown/证据，保留引用与未知项。只下载任务相关来源。正文与附件先上传不可变 hash 对象，再提交候选；worker 使用独立、可撤销、限定范围的 API 凭证，不分发数据库口令。
4. **数据库接收草稿。** 每次提交带稳定 `idempotency_key`、候选 hash、任务 epoch 和逐节点基线。事务比较当前草稿 head；不同节点可独立成功，同一节点过期基线返回 409 与差异。默认不自动拼接同节点不同段落，避免来源、双语正文和证据失配。提交成功返回持久收据；断线先按提交 ID 查状态，再决定续传，不能盲目重放。
5. **审核与发布分离。** 来源与结构校验通过后进入网页待审区。你审核准确的候选 hash；候选变化使旧批准失效。发布事务再次核对节点和书目依赖，只重建受影响产物，准备完整后原子切换发布指针。公众读不到未批准草稿；失败保留旧发布。worker 不因取得编辑权限自动取得发布权限。

例如电脑 A 编辑鸟类，电脑 B 编辑两栖，电脑 C 编辑植物，可以同时提交；若 A 与另一台电脑改到同一个鸟类节点，第二份过期提交保留为待解决候选，不覆盖已提交版本。若它们新增或更正同一条参考文献，保存书目新修订并显式绑定依赖；不能覆盖共享书目旧记录。

## 需要补充的数据结构与接口

现有 `outbox_job.lease_until` 只是通用任务基础，缺少 worker 身份、领取方、栅栏 epoch 和明确编辑范围；不能宣称已有完整并发协调。

| 待补结构 | 用途 |
|---|---|
| `worker_identity` / 凭证摘要与撤销记录 | 电脑/worker 身份、允许编辑范围、最后活动；记录凭证摘要，不存可直接使用的明文 token |
| `authoring_task` + `task_node` | 类群/主题、冻结节点集合、领取方、租约与 epoch、任务进度及基线 |
| `draft_head` + `change_set_node` | 按节点 CAS 更新草稿 head，记录期望/候选修订；批次提交保持事务边界 |
| 提交回执、冲突与审核状态 | 幂等查询、断线恢复、候选差异和审批状态；复用现有 change_set/validation/approval 表 |
| 用户工作区表 | 需要跨电脑同步的笔记、收藏和查询历史，保留原本的用户归属与导入来源 |

目标接口包括任务 claim/heartbeat、按节点和版本取得内容包、候选提交与回执查询、校验状态、网页 diff/preview/approve/publish/rollback。只有管理端能调发布接口。分类只读接口的 v1 `packed-adjacency` 与新 v2 `indexed-relations` 契约要显式过渡，不虚报内部结构。

## 实施与验收顺序

1. 补完来源和运行资源的去重清单、对象路由及容量预算，继续使用现有 Neon/Blob，不新建平行库。
2. 实现并发草稿与 worker API/CLI，先让两台电脑真实提交不同节点；验证同节点竞争、租约失效、断网与幂等恢复。
3. 实现网页来源/差异/预览审核、候选批准与原子发布；真实验证一次引用变更和一次回滚。
4. 完整运行资源接入、公开读取与 native-core 契约验收后，再切生产并将数据库确定为唯一创作权威。

本轮没有变更生产，也没有声称新增功能已经可用。
